# Задача 1

## FURPS+

| Код | Требования | Комментарий (Обоснование) |
| :--- | :--- | :--- |
| **F** | **Функциональные (Functionality)** | |
| F-01 | **Сайт:** Отображение списка депозитов с актуальными ставками | Исключает риск предоставления клиентам устаревшей информации из-за ручного обновления Excel. |
| F-02 | **Сайт:** Сбор заявки на депозит (ФИО, телефон) с последующим звонком КЦ | Позволяет начать процесс цифровизации без полной автоматизации бэк-офиса (MVP подход). |
| F-03 | **Сайт:** Подача заявки на кредит с паспортом (опционально) для мгновенного решения | Снижает время ожидания клиента за счёт онлайн-скоринга вместо офлайн-процесса. |
| F-04 | **Интернет-банк:** Персонализированные ставки по депозитам для авторизованных клиентов | Повышает конверсию за счёт использования внутренней истории клиента (Cross-sell). |
| F-05 | **Интернет-банк:** Открытие депозита со счёта клиента с подтверждением СМС | Обеспечивает юридическую значимость операции и защиту от несанкционированных действий. |
| F-06 | **Интернет-банк:** Предодобренные кредитные предложения (Pre-approved) | Ускоряет процесс выдачи кредита до 1 дня, устраняя необходимость первичного анализа вручную. |
| F-07 | **Бэк-офис:** Единый интерфейс управления ставками (вместо Excel) | Устраняет риски ошибок при ручном расчёте в файлах. |
| F-08 | **Интеграция:** Продолжение заявки из Сайта в Отделении (единый ID заявки) | Предотвращает дублирование данных и улучшает клиентский опыт (Omni-channel). |
| F-09 | **Уведомления:** СМС о статусе заявки (депозит/кредит) без доработки ядра подрядчика | Снижает зависимость от вендора и стоимость владения системой (реализация через обходной сервис). |
| **U** | **Удобство использования (Usability)** | |
| U-01 | Время отклика интерфейса < 200 мс (локальные операции) | Прямое влияние на конверсию: задержки >1 сек приводят к оттоку пользователей в онлайн-каналах. |
| U-02 | Соблюдение единой дизайн-системы банка во всех каналах | Снижает когнитивную нагрузку на клиентов, использующих несколько каналов одновременно. |
| U-03 | Минимальное количество шагов в воронке заявки | Каждый дополнительный шаг снижает конверсию на 10-20% (эмпирическое правило финтеха). |
| **R** | **Надёжность (Reliability)** | |
| R-01 | Доступность сервисов 99,9% (SLA) | Критично для репутации банка при продвижении онлайн-каналов как основного способа обслуживания. |
| R-02 | Изоляция сбоев новых сервисов от АБС (Circuit Breaker) | Защита легаси-ядра (АБС) от перегрузки трафиком из новых каналов. |
| R-03 | Возможность переключения на резервный ЦОД | Требование регулятора и бизнес-непрерывности при авариях в основном дата-центре. |
| R-04 | Гарантия доставки транзакционных СМС (статусы заявок) | Юридическое требование информирования клиента о движении средств/статусе договора. |
| **P** | **Производительность (Performance)** | |
| P-01 | Кэширование справочных данных (ставки, курсы) | Снимает нагрузку с АБС при частых чтениях, решая проблему загрузки >1 сек. |
| P-02 | Обработка предодобренных кредитов в течение рабочего дня | Бизнес-требование конкурентоспособности: текущий batch-процесс (раз в сутки) неприемлем для онлайн-продаж. |
| P-03 | Горизонтальное масштабирование новых сервисов | АБС масштабируется только вертикально, новые каналы должны принимать удар нагрузки на себя. |
| P-04 | Защита системы скоринга от пиковых нагрузок (асинхронность) | Скоринг — узкое место, синхронные запросы от всех каналов вызовут деградацию процесса кредитования. |
| **S** | **Поддерживаемость (Supportability)** | |
| S-01 | Использование стека банка (Java, .NET, Python, Oracle/MS SQL) | Снижает затраты на обучение и позволяет использовать внутреннюю экспертизу (Time-to-Market). |
| S-02 | Документирование API (Swagger/OpenAPI) для всех новых сервисов | Обеспечивает возможность независимой разработки фронтенда и бэкенда разными командами. |
| S-03 | Логирование и мониторинг (APM) всех новых компонентов | Необходимо для соблюдения SLA 99,9% и быстрого выявления инцидентов (MTTR). |
| **+R** | **+ Ограничения (Restrictions)** | |
| +R-01 | Запрет прямой записи в БД АБС из новых каналов | **Критично:** Текущая схема (прямой доступ IB к БД АБС) является антипаттерном и угрозой стабильности. |
| +R-02 | Обязательная идентификация новых клиентов в отделении | Требование ФЗ-115 (ПОД/ФТ), нельзя полностью исключить визит без биометрии/ЕСИА. |
| +R-03 | Разделение доступа данных между депозитным и кредитным бэк-офисом | Требование безопасности, должно быть обеспечено на уровне ролевой модели. |
